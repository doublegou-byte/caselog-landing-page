# 腾讯云服务器首个网关部署

适用场景：

- 服务器：腾讯云 `Ubuntu 22.04-Docker26`
- 登录方式：可直接 `root` 登录
- 当前状态：已经有前端镜像，还没有搭第一个 `nginx` 网关
- 目标：先让 `www.caselog.cn` 访问当前静态官网，`api.caselog.cn` 预留给后端

这份文档现在覆盖两个阶段：

- 第一阶段：先用 `80` 跑通官网
- 第二阶段：切到 `acme.sh + DNSPod API`，为 `caselog.cn`、`www.caselog.cn`、`api.caselog.cn` 自动签发证书并启用 `443`

## 1. 先确认三件事

1. 腾讯云安全组当前至少已经放行 `80`
2. 域名已经解析到服务器公网 IP
3. 服务器里已经有 `docker` 和 `docker compose`

当前阶段端口建议：

- `80`：现在就放行，用于先把官网跑通
- `443`：启用 HTTPS 后放行
- SSH 管理端口：按你自己的实际登录端口单独控制，这份文档不假设一定开放 `22`

检查命令：

```bash
docker -v
docker compose version
```

## 2. 域名解析建议

在 DNS 里先配这三条：

- `www.caselog.cn` -> 服务器公网 IP
- `caselog.cn` -> 服务器公网 IP
- `api.caselog.cn` -> 服务器公网 IP

当前阶段：

- `www.caselog.cn`：走静态官网
- `caselog.cn`：跳转到 `www.caselog.cn`
- `api.caselog.cn`：先返回 `503`，等后端镜像准备好后再接入

## 4. 创建部署目录

```bash
mkdir -p /opt/caselog/deploy/gateway/conf.d
mkdir -p /opt/caselog/deploy/gateway/certs/web
cd /opt/caselog
```

推荐目录结构：

```text
/opt/caselog
  ├── docker-compose.yml
  └── deploy
      └── gateway
          ├── certs
          │   └── web
          └── conf.d
              └── default.conf
```

## 5. 写 docker-compose.yml

在 `/opt/caselog/docker-compose.yml` 写入：

```yaml
services:
  gateway:
    image: nginx:1.27-alpine
    container_name: caselog-gateway
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./deploy/gateway/conf.d:/etc/nginx/conf.d:ro
      - ./deploy/gateway/certs:/etc/nginx/certs:ro
    depends_on:
      - web

  web:
    image: crpi-had8j9la06ibxzbx.cn-shanghai.personal.cr.aliyuncs.com/three_engine/caselog-web:1.0.1
    container_name: caselog-web
    restart: unless-stopped
    expose:
      - "80"
```

说明：

- 现在只启动两个容器：`gateway` 和 `web`
- `gateway` 是外层网关
- `web` 是已经构建好的前端静态镜像
- 建议从 `1.0.1` 开始使用，因为这个版本起未知路径会返回 `404`
- 当前推荐的证书模式不是手动下载证书包，而是 `acme.sh` 自动写入 `gateway` 证书目录

## 6. 写网关 Nginx 配置

在 `/opt/caselog/deploy/gateway/conf.d/default.conf` 写入：

```nginx
server {
    listen 80;
    server_name caselog.cn;
    return 301 https://www.caselog.cn$request_uri;
}

server {
    listen 80;
    server_name www.caselog.cn;
    return 301 https://www.caselog.cn$request_uri;
}

server {
    listen 80;
    server_name api.caselog.cn;
    return 301 https://api.caselog.cn$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name caselog.cn;

    ssl_certificate /etc/nginx/certs/web/caselog.cn_bundle.pem;
    ssl_certificate_key /etc/nginx/certs/web/caselog.cn.key;

    return 301 https://www.caselog.cn$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name www.caselog.cn;

    ssl_certificate /etc/nginx/certs/web/caselog.cn_bundle.pem;
    ssl_certificate_key /etc/nginx/certs/web/caselog.cn.key;

    location / {
        proxy_pass http://web:80;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 443 ssl;
    http2 on;
    server_name api.caselog.cn;

    ssl_certificate /etc/nginx/certs/web/caselog.cn_bundle.pem;
    ssl_certificate_key /etc/nginx/certs/web/caselog.cn.key;

    default_type text/plain;
    return 503 "API not deployed yet\n";
}
```

这份配置现在的行为是：

- `http://caselog.cn` 自动跳到 `https://www.caselog.cn`
- `http://www.caselog.cn` 自动跳到 `https://www.caselog.cn`
- `https://caselog.cn` 自动跳到 `https://www.caselog.cn`
- `https://www.caselog.cn` 转发到前端容器 `web`
- `https://api.caselog.cn` 暂时直接返回 `503`

当前推荐是一张证书同时覆盖：

- `caselog.cn`
- `www.caselog.cn`
- `api.caselog.cn`

这样 API 还没接后端时，HTTPS 也已经是正确的。

## 8. 先用 80 跑通，再切 HTTPS

如果这是第一次从零部署，建议先让 `80` 和前端镜像跑通，再做证书签发。

先验证：

```bash
curl -I -H "Host: www.caselog.cn" http://127.0.0.1
curl -I -H "Host: api.caselog.cn" http://127.0.0.1
```

确认 `gateway + web` 正常后，再做下一节的 `acme.sh`。

## 9. 用 acme.sh 自动签发和续期

推荐固定成这条路径：

1. 在 DNSPod 创建 API Token
2. 在服务器安装 `acme.sh`
3. 使用 `dns_dp` 为三个域名签发同一张证书
4. 让 `acme.sh` 把证书安装到 `/opt/caselog/deploy/gateway/certs/web`
5. 续期后自动执行 `docker exec caselog-gateway nginx -s reload`

安装：

```bash
curl https://get.acme.sh | sh -s email=your-email@example.com
/root/.acme.sh/acme.sh --set-default-ca --server letsencrypt
```

导出 DNSPod 凭据：

```bash
export DP_Id="你的DNSPod Token ID"
export DP_Key="你的DNSPod Token Key"
```

签发：

```bash
/root/.acme.sh/acme.sh --issue \
  --dns dns_dp \
  -d caselog.cn \
  -d www.caselog.cn \
  -d api.caselog.cn \
  --keylength 2048
```

如果第一次签发时 DNS 传播较慢，可以改成：

```bash
/root/.acme.sh/acme.sh --issue \
  --dns dns_dp \
  -d caselog.cn \
  -d www.caselog.cn \
  -d api.caselog.cn \
  --keylength 2048 \
  --dnssleep 180
```

安装到网关证书目录：

```bash
/root/.acme.sh/acme.sh --install-cert -d caselog.cn \
  --key-file /opt/caselog/deploy/gateway/certs/web/caselog.cn.key \
  --fullchain-file /opt/caselog/deploy/gateway/certs/web/caselog.cn_bundle.pem \
  --reloadcmd "docker exec caselog-gateway nginx -s reload"
```

说明：

- 不要手工修改 `caselog.cn_bundle.pem` 和 `caselog.cn.key`
- 如果 DNSPod Token 暴露过，应立即轮换
- 续期成功后会自动 reload `gateway`，不需要手动重启容器

## 10. 当前证书目录和续期方式

当前服务器上的网关证书目录建议固定为：

```text
/opt/caselog/deploy/gateway/certs/web
```

当前实际使用的证书文件是：

- `/opt/caselog/deploy/gateway/certs/web/caselog.cn_bundle.pem`
- `/opt/caselog/deploy/gateway/certs/web/caselog.cn.key`

这些文件通过 `docker-compose.yml` 挂载进 `gateway` 容器，再由 Nginx 的 `ssl_certificate` 和 `ssl_certificate_key` 引用。

## 11. 验证

在服务器本机验证：

```bash
curl -I http://www.caselog.cn
curl -I https://www.caselog.cn
curl -I https://caselog.cn
curl -I https://api.caselog.cn
curl -I https://www.caselog.cn/wp-admin/setup-config.php
```

预期：

- `http://www.caselog.cn` -> `301`
- `https://www.caselog.cn` -> `200`
- `https://caselog.cn` -> `301` 到 `https://www.caselog.cn`
- `https://api.caselog.cn` -> `503`
- `https://www.caselog.cn/wp-admin/setup-config.php` -> `404`

```yaml
image: crpi-had8j9la06ibxzbx.cn-shanghai.personal.cr.aliyuncs.com/three_engine/caselog-web:1.0.2
```

然后执行：

```bash
cd /opt/caselog
docker compose pull
docker compose up -d
```

证书续期和镜像更新是两条线，不需要绑在一起。

## 13. 后续接入 API

等后端镜像准备好后，补两件事：

1. 在 `docker-compose.yml` 里加 `api` 服务
2. 把 `api.caselog.cn` 的 `503` 配置改成反向代理

替换为：

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name api.caselog.cn;

    ssl_certificate /etc/nginx/certs/web/caselog.cn_bundle.pem;
    ssl_certificate_key /etc/nginx/certs/web/caselog.cn.key;

    location / {
        proxy_pass http://api:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
